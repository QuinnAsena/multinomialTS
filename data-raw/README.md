# data-raw

Provenance and maintenance for the datasets in `data/`. This directory is
`.Rbuildignore`d and is not installed with the package.

## What is bundled

| Dataset | What it is | Source |
|---|---|---|
| `story_pollen_wide` | Story Lake pollen counts, ages and depths | doi:10.1111/1365-2745.14289 |
| `story_char_wide` | Story Lake charcoal accumulation rate | doi:10.1111/1365-2745.14289 |
| `story_pollen_matrix` | `story_pollen_wide` binned to 50-year resolution | derived — see below |
| `story_char_matrix` | `story_char_wide` binned to 50-year resolution | derived — see below |
| `sunfish_pollen_wide` | Sunfish Pond pollen counts and ages | Johnson et al., in review |
| `sunfish_ll` | Sunfish Pond lake-level reconstruction | Johnson et al., in review |

The two `*_matrix` objects are the binned, model-ready form of the corresponding
`*_wide` tibbles. The binning recipe is not duplicated here because it is the
subject of the main vignette — see the "Data processing" section of
`vignettes/multinomialTS-vignette.qmd`, which derives exactly these matrices step
by step from the wide tibbles.

Note that `story_char_matrix` is **not** scaled. Scale it (`scale()`) before
passing it to `mnGLMM()` or `mnTS()`, as the vignette and the examples do.

## What is deliberately *not* bundled

Bootstrap output. Up to version 1.0.3 the package shipped `story_100_bootstraps`
and `bootstrap_sensitivity`, both produced by `boot.mnTS()`.

Those objects were removed in 1.1.0 for two reasons:

1. **They go stale silently.** Both were generated by the pre-1.1.0
   `simulate.mnTS()`, which drew every replicate with a hard-coded multinomial
   size of 100 instead of the observed totals. Fixing that changed all bootstrap
   standard errors, which left the shipped objects misleading with nothing to
   flag it.
2. **Size.** `bootstrap_sensitivity` retained the complete fitted models in its
   `all_mods` element and accounted for roughly 99% of the installed data.

The general lesson: model-derived objects should not be bundled as package data,
because nothing ties them to the version of the model that produced them. The
vignettes now show the bootstrapping code instead — the main vignette runs a small
bootstrap live, and the Sunfish Pond vignette carries the wrangling and plotting
code un-executed for reference.

## Maintenance

`fix-datasets.R` applies the 1.1.0 data corrections (dropping stray `grouped_df`
groupings, renaming the truncated `P.strobu` column to `P.strobus`, and
recompressing with xz). It is idempotent.
